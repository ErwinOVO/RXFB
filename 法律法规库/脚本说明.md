# 脚本索引

> 2026-09-14 更新：**三脚本流水线**已合并完成。原先散落在 `爬虫/`（10 个）与 `入库/`（17 个）的脚本，
> 按「爬数据 → 处理数据 → 入库」三阶段收敛为**三个单文件自包含脚本**，业务逻辑零改动（逐行搬运）。
> 旧脚本已备份至 `_legacy/`，验证通过后可手动删除。
>
> **路径说明**：三个脚本都自动向上查找项目根（含 `法规库.db` 或 `.workbuddy` 的目录），
> 从任意位置运行都能正确读写数据，不需要先 `cd`。

## 流水线总览

```
阶段一 爬数据.py     原始数据获取（官网抓取 / 附件正文 / OCR）
      ↓  人民银行/ · 国家金融监督管理总局/ · 外汇局/ · iweicha/
阶段二 处理数据.py   清洗与合并（跨源去重 / 正文体检 / 排除清单）
      ↓  待入库_v2/
阶段三 入库.py       灌库与回填（schema 迁移 / 主入库 / 字段补齐 / 分类 / 索引）
      ↓  法规库.db
```

三个阶段**按顺序执行，每步幂等**，可重复跑。每步独立 try/except，单步失败只跳过该步，不中断流程。

## 阶段一：`爬数据.py`

抓取四个来源的原始数据，并把「正文在附件里」的条目补出正文。

| 步骤 | 内容 | 说明 |
|---|---|---|
| 1 | **NFRA 盘点** | 金监总局官网政策规章（`http.cookiejar` 维持 session；长链 Referer） |
| 2 | **人行** | 官网三栏目：行政法规 / 部门规章 / 规范性文件 |
| 3 | **外汇局** | 官网「政策法规」`zcfg` 栏目（详见下方说明） |
| 4 | **iweicha** | 金监局 type=1 + 人行 type=2（type=3 外汇局未启用） |
| 5 | **汇总 iweicha 索引** | 写 `iweicha/_index.csv` |
| 6 | **补取原文链接** | 抓原始机构官网 URL 回写 `_meta.json` |
| 7 | **下载附件 + 补附件正文 + OCR** | PDF 文字提取（pypdf）→ 扫描件 OCR；产出 `{原始条目目录}/_body.txt` |

**外汇局（步骤 3）的两个要点**：

- `/safe/zcfg/` 是 21 个栏目的**全量聚合视图**。实测它与 20 个专栏目双向差集均为 0（各 558 条），
  所以只抓它 28 页即得全部条目，不必逐栏目抓 59 页。栏目标签不丢——写在详情页 `<title>` 的 `_栏目_` 里。
- 详情页 `div.detail_conbg` 是一张**结构化公文元数据表**（`<li><dt>标签</dt><dd>值</dd></li>`），
  文号 / 发布日期 / 来源 / 分类 / 索引号 逐字段直取，不用从正文正则里猜。
  注意标题里含文号的只有 16/558，**文号必须走这里取**。
- 该站无 WAF、无 robots.txt、不需要 cookie/session/JS，纯静态 HTML。
- **限速**：默认单线程 + 每次请求前随机等 `2.5~3.1` 秒（同 NFRA / PBC 的 jitter 做法）。
  整步 28 个列表页 + 558 个详情页 ≈ **586 个请求 → 约 30 分钟**（≈ 0.32 请求/秒）。
  间隔会**按并发等比放大**（`safe_delay_window`），所以总节奏与 `--workers` 无关，
  默认 1/4/8 并发都是 28~30 分钟；调大并发只用于个别请求卡住时补位。
  临时改总时长用 `--safe-interval SEC`（平均间隔秒数）：`5.6` → 约 60 分钟，`1.4` → 约 17 分钟。
  实测 3 次请求 9.5 秒 → 0.32 请求/秒，与预估吻合。

```bash
python 爬数据.py                    # 全流程
python 爬数据.py --dry-run          # 只盘点，不写文件
python 爬数据.py --only safe        # 只跑外汇局（nfra/pbc/safe/iweicha/links/attachments）
python 爬数据.py --only safe --limit 30        # 先抓 30 条试跑
python 爬数据.py --only safe --safe-interval 5.6   # 放慢到约 60 分钟
python 爬数据.py --skip-link        # 跳过「补取原文链接」
python 爬数据.py --skip-ocr         # 跳过 OCR
python 爬数据.py --workers 8        # 指定并发（外汇局节奏不受影响）
python 爬数据.py --types 1,2        # iweicha 机构类型
python 爬数据.py --year 2025        # iweicha 限定年份
```

**依赖降级**：Playwright / pypdf / OCR 服务缺失时**自动跳过该步并提示**，不中断流程。

## 阶段二：`处理数据.py`

把阶段一的原始数据合并去重，产出规范的「待入库」结构。

| 步骤 | 内容 | 产出 |
|---|---|---|
| 1 | **整理待入库** | 合并 iweicha 与官网，去重，按机构落盘 → `待入库_v2/{机构}/{source_id}_{标题}/` |
| 2 | **正文体检** | 分级统计正文完整性 → `_正文体检.csv` |
| 3 | **补详情正文** | 对官网残缺正文，从 `detail.json` 的 `docClob` 补全 |
| 4 | **生成排除清单** | 把无法补救的条目列为不入库 → `_排除清单.csv` |

```bash
python 处理数据.py                  # 全流程
python 处理数据.py --dry-run        # 只分析，不写文件
python 处理数据.py --only merge     # 只跑某一步
python 处理数据.py --tu 待入库_v2    # 指定输出目录
```

**正文取舍规则**（「附件正文双轨制」）：
- `content.txt` = 页面正文；`_body.txt` = 阶段一从附件/OCR 提取的正文
- 页面正文「正常」（≥120 字且不像附件名）→ 优先用页面正文
- 否则取更长的那个（避免 21 字的附件文件名顶掉 1120 字的真正文）

## 阶段三：`入库.py`

把「待入库」灌进 `法规库.db`，并把迁移、回填、分类、索引一次跑完。

| 步骤 | 内容 | 说明 |
|---|---|---|
| 1 | **schema 迁移** | v1→v2：hierarchy / issuer / regulation_issuer + 加列。**改库前自动备份** |
| 2 | **分类迁移** | `reg_category` 加 `is_primary`；「央行专项」7 专题；专题排序；融资担保并入地方金融 |
| 3 | **主入库** | 逐条灌 `regulation`（判重 / 机构 / 层级 / 分类 / 指纹） |
| 4 | **补早期18条** | 补 `source_id` / `scope` / `content_hash` |
| 5 | **补文号** | 从标题抽文号回填 `doc_number`（只补空） |
| 6 | **补发布日期** | 从 iweicha `detail.html` / 正文落款解析 `pub_date` |
| 7 | **校正发布日期** | 修正 `pub_date` 与文号年份冲突的条目 |
| 8 | **补生效日期** | 从正文附则挖施行日期回填 `effective_date` |
| 9 | **重跑分类** | 用 `category_rules.json` 重建 `reg_category`（主/辅分类） |
| 10 | **重建索引** | 从各条目 `_meta.json` 重建 `_index.csv` |

```bash
python 入库.py                      # 全流程（会写库）
python 入库.py --dry-run            # 只分析，不写库
python 入库.py --only regs,classify # 只跑某几步
python 入库.py --tu 待入库_v2        # 指定待入库目录
python 入库.py --verbose            # 打印判重跳过明细
```

**判重三档键**，优先级：① **文号**（归一化 `norm_docno` 后比较）② `source_id` ③ 标题归一化 `norm_title`

- `source_id` 档必需：像「中国人民银行 公告」这类标题归一化后为空/过短的条目，
  标题与文号都拦不住，只能靠它，否则重跑会重复入库。
- 文号比较必须归一化：来源之间写法常有出入（`国务院令 第297号` vs `国务院令第297号`、
  `银监发〔2006〕７号` vs `银监发〔2006〕27号`），直接比字符串会把重复当新版放行。
- **版本感知**（`VERSION_AWARE_SOURCES = ("safe",)`，目前**只对外汇局启用**）：
  `norm_title` 会把 `（已废止）`/`（已修改）` 前缀剥掉，同族版本归一化后完全同名。
  外汇局把 1987 年以来的所有版本都挂在网上（实测 558 条里有 18 组同标题），
  **只按标题跳过会误杀 25 条修订版**。所以对 `safe:` 来源，标题相同时**再比文号**：
  双方都有且不同 → 判为不同版本，放行。

> ⚠️ **为什么暂不对人行 / 金监总局启用**：开启后现有 2897 条会多出 9 条历史版本
> （如「人民币跨境支付系统业务规则」银发〔2018〕72号 vs 库内银发〔2025〕248号）。
> 那 9 条**本身是漏收**（文号、日期、正文都不同，已逐条比对），数据是对的，
> 但属于超出「接入外汇局」范围的变化，留待后续单独评估后再开。
> 另注：`iweicha` 源里有同一文件两条记录、文号一个写 `７号` 一个写 `27号` 的情况
> （经核实 27 号才对），启用版本感知时会因此产生 1 条重复，需先修正该条文号。

## 几个已知注意事项

1. **NFRA 必须用长链 Referer** —— 短链 `itemId=928` 会路由到 nginx 兜底返回假 200 空数据，长链才路由到 X-WEB 真后端。
2. **iweicha `file_id` 跨机构撞号** —— 判重/排除必须用 `(机构, source_id)` 组合键；入库时 `source_id` 加机构后缀（`iweicha-pbc:` / `iweicha-nfra:`）。
3. **`load_dicts()` 明确不用 `former_names` 做机构识别** —— 否则标题里的「中国银监会」会同时算到「国家金融监督管理总局」和「中国银行业监督管理委员会」头上。`former_names` 只用于检索同义词展开。
4. **正文取舍** —— 页面正文「正常」（≥120 字且不像附件名）优先；否则取更长的。改动过的地方：人行官网「仅附件名」从 64 条 → 0 条。
5. **`处理数据.py` 不用 `shutil.rmtree` 整体删目录** —— Windows + 杀毒扫描下删 2392 个目录要 11 分钟+。改为「覆盖写 + 事后清理多余目录」，耗时 11 分钟 → 171 秒。
6. **iweicha 原链有约 225 条取不到** —— 实测是平台侧问题（弹「此文件还没有原文链接！」或服务端空引用异常），非脚本问题。
7. **跑 `入库.py` 前建议先备份 `法规库.db`** —— 脚本内部在 schema 迁移前会自动备份一次（`法规库_backup_<时间戳>.db`），确认无误后可手动删除。
8. **外汇局总页数藏在「尾页」链接里** —— 该站不用「共N页」文本，要解析 `title="尾页"` 的 href 取 `index_N.html` 的 N。
9. **外汇局元数据区必须按单元格解析** —— 结构是 `<ul><li><dt>标签：</dt><dd>值</dd></li></ul>`。**不能用「标签行 + 取下一行当值」的文本法**：很多老文件没有文号，`<dd>` 是空的，空行会被过滤掉，于是把后面正文第一行当成值（实测把「文号」抓成了标题、「分类」抓成了「来 源：」标签）。另外标签用 `&nbsp;` 对齐，去空白必须用 `\s` 正则，`str.replace(" ")` 去不掉 `\xa0`。
10. **列表页标题有截断** —— 558 条里 155 条带「…」。`_meta.json` 的 `title` 必须取详情页的完整标题（优先元数据区「名 称」），否则判重不准。
